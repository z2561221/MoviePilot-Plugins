# LocalToolkit V3

工具中心是 MoviePilot V3 本地专属维护插件，把三个本地工具收敛到一个插件入口：清理库存、扫描缺集、清TMDB。插件只发布在本地插件源（元数据位于 `package.local.v3.json`，同步时物化为本地仓库的 `package.v3.json`），不进入公共插件市场。
`v3.0.0`：适配V3接口与独立代际加载；隔离分身前端请求；扫描清理独立调度、分批执行与冷却补跑；修复管理器兼容导入。；管理接口仅允许超级用户访问；操作反馈紧凑显示，成功提示 5 秒后收起。

## 模块构成

| 模块 key | 名称 | 触发方式 |
| --- | --- | --- |
| `library_cleanup` | 清理库存 | 独立扫描周期 + 独立清理周期 + 手动 |
| `check_missing` | 扫描缺集 | 仅手动 |
| `tmdb_cache` | 清TMDB | 仅手动 |

只有清理库存会注册 MoviePilot 后台服务；扫描缺集与 TMDB 缓存清理是按需模块，不再拥有 cron 配置，插件停用时不返回任何服务条目。

## 启用前提

- 插件总开关 `enabled` 打开后才会注册后台服务。
- `library_cleanup.scan_enabled` 和 `cleanup_enabled` 分别控制周期扫描与周期清理；媒体服务器、媒体库与用户共用同一配置。
- 扫描缺集需要在 `check_missing.scan_paths` 填写可访问的本地目录，每行一个。
- 清TMDB需要可用 Redis；连接地址取 `CACHE_BACKEND_URL`，默认 `redis://localhost:6379`。

首次启用会从旧插件 `ClearTmdbCache`、`CheckMissing`、`LibraryCleanup` 迁移配置，并写入 `migration_done` 防止重复迁移。

## 配置要点

清理库存

- `scan_cron`：扫描周期，新配置默认 `9 0 * * *`，只更新清理计划。
- `cleanup_cron`：清理周期，新配置默认 `0 * * * *`，只处理已有计划。
- 旧 `enabled`、`cron`、`notify` 在新字段缺失时分别迁移到两组设置；已有实例保留原周期与通知开关，不自动提高清理频率。
- `cycle_cooldown_minutes`：两轮清理开始时间的最短间隔，默认 `60` 分钟；冷却期间跳过清理，不影响独立扫描。
- `selected_server`、`selected_library`、`selected_user`：媒体服务器、媒体库与判定播放状态所用用户。
- `filter_played`、`filter_favorite`、`days_threshold`：第一组条件，默认已播放、未收藏、20 天。
- `filter_played_2`、`filter_favorite_2`、`days_threshold_2`：第二组条件，默认未播放、未收藏、40 天；两组条件按并集取候选。
- `auto_delete`、`auto_delete_delay`、`auto_delete_max_count`、`dry_run`：自动删除开关、延迟秒数、每周期删除数量与演练模式。数量默认 10，可在设置页调整；自动删除默认关闭。
- `scan_notify`：计划新增或失效移出时发送摘要；无变化时只记录运行历史。
- `cleanup_notify`：本批清理结果通知，Telegram 更新本批同一条 HTML 消息，其他渠道只接收最终结果。空计划、冷却、忙碌或自动删除关闭时不推送。
- 持续异常按操作和目标范围去重，同一异常 24 小时内不重复通知，恢复后提醒一次；发送失败不开始通知冷却。

扫描缺集

- `scan_paths`：待扫描目录，多行输入。
- `skip_empty`：跳过空目录，默认开启。
- `notify`：扫描结果通知，默认开启；Telegram 按路径、剧集和季度显示 HTML 报告，长清单保留总数及省略提示，其他渠道使用纯文本。

清TMDB

- `threshold_mb`：缓存体积阈值，默认 50 MB。
- `auto_clear`：达到阈值时自动清理，默认关闭。
- `notify`：清理结果通知，默认开启，使用简短纯文本回执。

## API 路由

全部路由使用 `bear` 认证，由 Vue 联邦组件通过宿主注入的客户端调用。

| path | method | 用途 |
| --- | --- | --- |
| `/local_toolkit/status` | GET | 读取三模块运行状态 |
| `/local_toolkit/run/{module}` | POST | 手动运行指定模块 |
| `/local_toolkit/history` | GET | 分页读取运行历史 |
| `/local_toolkit/options` | GET | 读取媒体服务器、媒体库与用户候选 |
| `/local_toolkit/invalidate_cache` | POST | 失效候选与选项缓存 |
| `/local_toolkit/cleanup_plan` | GET | 分页读取持久化清理计划 |
| `/local_toolkit/cleanup_plan/scan` | POST | 完整扫描并合并清理计划，不执行删除 |
| `/local_toolkit/cleanup_plan/clear` | POST | 清空清理计划，不删除媒体库条目 |
| `/local_toolkit/cleanup_plan/recheck` | POST | 只读核验单条或异常批次，返回逐项处理结果 |

清理计划中点击单条“重新核验”，或“核验异常”批量处理。核验只查询媒体状态：已不存在或条件不符则移出计划，仍符合条件则清除旧错误恢复待处理，无法核验则保留并显示原因和处理办法。媒体条目不会被删除，也不触发通知、扫描或清理冷却。批量每次最多 10 部，耗时较长时会提前返回已完成结果与未核验数量，后续批次优先核验尚未检查的异常项。请求体省略 `queue_key` 时选择异常批次；单条必须传入计划返回的完整 `queue_key`，条目失效时不会扩大成批量操作。

`history` 接受 `page` 与 `page_size`，非法值会被收敛，返回 `total`、`page`、`page_size`、`total_pages` 和 `items`；历史存储损坏时返回空列表而不是报错。

清理计划采用紧凑列表和底部分页，每页条数随可用高度调整，桌面最多 15 条，移动端按紧凑行高度计算。条目详情按钮提供完整名称、状态原因、处理办法和最近核验时间；核验结果通过“查看核验结果”打开，不挤占列表空间。

## 运行流程

1. 周期扫描分页读取配置范围内的电影和普通视频，按当前两组条件筛选；完整读取成功后才提交计划。读取失败、重复页或缺页会保留原计划。
2. 扫描按“媒体服务器 + 条目 ID”合并新增项，并将新条目追加到清理计划末尾；已失效项移出，必要筛选字段未知的已有对象保留待复核。扫描不会自动接着执行清理，也不会重置清理冷却。
3. 周期清理与手动“立即清理”仅读取持久化计划；空计划、冷却中、自动删除关闭或演练模式直接返回回执，不扫描、不删除、不推送。
4. 每轮从计划头部按入队顺序选择设置数量的对象；跳过或失败不会扩大本批数量。每个对象在删除前重新读取当前用户的收藏、观看状态及入库时间。移出配置范围或条件不符则跳过，明确不存在则移出计划，权限错误或字段不完整则保留，禁止用旧快照删除。
5. 嵌套目录通过当前条目的祖先链确认媒体库归属，不枚举整库；条目身份不一致时拒绝删除。删除间隔结束后才读取下一项当前状态。
6. 第一项实际删除前发送 Telegram 报告，删除与复核阶段编辑原消息；未实际删除的批次只发最终结果。报告保留本批名单及移除、跳过、仍存在、无法核验、剩余计数。
7. 删除后对实际尝试的媒体 ID 做最多三轮复核；已移除项出队，失败或未知项保留尝试次数与原因及原队列位置，下一轮仍从计划头部按顺序处理。复核只确认媒体库条目状态。
8. 本轮开始时间先持久化，手动与定时清理共同遵守冷却。扫描失败和清理异常分别保存及恢复，空计划或冷却跳过不冒充恢复。
9. 每轮写入最近 30 条 `tool_history`；扫描与清理各自保留最近结果，计划保存在 `library_cleanup_plan`，通知去重状态使用插件自身数据命名空间。
10. 扫描缺集和 TMDB 缓存仍只按需执行，配置与通知行为保持各自模块原有方式。

## 边界与限制

- 清理库存直接由工具中心实现，不导入也不加载旧的独立 `LibraryCleanup` 插件；旧配置迁移只发生在 `service/lifecycle.py`。
- `modules/` 下的文件只是兼容 shim，不承载业务编排与外部边界。
- 扫描缺集与 TMDB 缓存清理不得恢复 cron 配置或后台服务注册。
- 删除是不可逆操作：`auto_delete` 与 `auto_delete_max_count` 共同限制本轮影响面，验收阶段建议先用 `dry_run`。
- 删除后复核只确认媒体库条目状态，不证明磁盘文件已经删除；复核不会启动新一轮清理或重复发出删除请求。
- Telegram 回执缺失或编辑失败时不另发一份完成报告；记录通知失败并保留本轮结果。旧宿主缺少回执或编辑接口时，仅在结束后发送一次报告。其他渠道接收一次纯文本结果。
- 扫描与清理共用互斥锁；定时碰撞时串行等待，手动忙碌时立即返回提示。同一插件对象重新初始化仍复用运行锁，旧定时回调会被禁用。
- 前端不硬编码任何浏览器侧 token，`api.js` 只读取宿主返回的 `response.data`，不做二次解包。
- 渲染模式固定为 `("vue", "dist/assets")`；`remoteEntry.js` 与其引用的 hash 资源必须同时存在。
- 移动端在 600px 以下把历史表格改为卡片展示，验收覆盖 390px、768px、1440px。

## 常见故障

| 现象 | 可能原因 | 处理方向 |
| --- | --- | --- |
| 插件启用但无清理计划 | 周期扫描未启用或尚未运行 | 开启周期扫描，或手动生成清理计划 |
| 候选列表为空 | 未选媒体库/用户，或两组条件过严 | 检查服务器、媒体库、用户与天数阈值 |
| 选项下拉为空 | 媒体服务器不可达或缓存过期 | 确认媒体服务器连接后调用 `invalidate_cache` |
| 缺集扫描无结果 | `scan_paths` 为空或路径不可访问 | 填写容器内可访问的绝对路径 |
| TMDB 缓存状态未知 | Redis 连接失败 | 检查 `CACHE_BACKEND_URL` 与 Redis 可用性 |
| 有候选但未删除 | `dry_run` 打开或 `auto_delete` 关闭 | 确认演练模式与自动删除开关 |
| 历史为空 | `tool_history` 存储损坏后已重置 | 重新运行一次模块即可写入新记录 |

## 运行要求

- MoviePilot `>= 3.0.0`
- MoviePilot V3 原生插件格式与 Vue 联邦渲染
- 清理库存需要可用媒体服务器（Emby 等）
- 清TMDB需要可用 Redis
- 本地插件源安装，不经公共插件市场分发

管理权限：所有工具中心 API 均要求已认证超级用户；普通用户返回 403，认证失败返回 401。API Key 沿用宿主认证结果，不绕过权限校验。
