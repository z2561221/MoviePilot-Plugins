# DownloadManagerLocal V3

下载中心是 MoviePilot V3 原生插件，把转移做种、IYUU 辅种、同步删除、种子重命名、站点标签、做种校验、下载速度监控和上传限速聚合到一个插件里，并通过 Vue 联邦页面提供配置、运行总览与只读诊断。

`v3.3.19`：[1]完善标签补全与保护;[2]扩展Pieces缺口铺种;[3]修复停止重载与转种

停止和重载按原执行代次收口：慢查询返回后，旧转种、铺种、补刀、标签清理及速度告警不能借新周期继续写入；初始化失败会释放本轮已启动的资源。已经发出的下载器或通知请求不能保证撤销，需回读核验，不直接重放。

转种添加前核验 `.torrent` 原始 `info` 与源任务 hash，添加回执异常时保留源任务；补 Tracker 在内存完成，原始 `info` 不被重新编码。标签修改在实例共享锁中按有限目标批次执行，Transmission 保留当前其他标签；人工清理也不能绕过宿主及管理锚点保护。

后台补标签结果按当前任务归属发布，旧扫描不覆盖新结果；被新任务取代的结果不再显示为可用。结果页只复制当前切片，避免为一页展开完整种子关联；JSON 文件读取和真实下载器请求的耗时仍需按现场分别观察。

## IYUU铺种

IYUU 为主要匹配来源，Pieces 按配置的 Passkey 站点补查缺口。沿用 IYUU 开关、Token、辅种下载器和执行周期；勾选“立即运行一次”并保存即可执行。没有独立匹配方式或预览、运行入口。每行填写 `站点名称:Passkey[:请求间隔秒数]`，站点名称对应 MoviePilot 站点管理中的唯一名称；留空仅使用 IYUU。

同是 Pieces 接口，入口却不一定一样。跟随青蛙辅种助手的协议分流，但域名保留 MoviePilot 现配置：青蛙、AGSVPT、红豆饭、麒麟、UBits、聆音及其他通用站点使用 `/api/pieces-hash`，朋友使用 `/api/torrents/pieces-hash`，憨憨使用 `/nexusapi/pieces-hash`；这些站点的下载沿用 Nexus `download.php` 约定。`ret` 非零的业务错误不会被空字典掩成成功，HTTP 404 也不会当作正常空命中。内置路径不代表站点当前接口必然可用。

FluxTorrent／好学使用 `站点名称:fxo_开头的开放API令牌[:请求间隔秒数]`，令牌需有 `crossseed` 权限。精确站名或 `fxo_` 令牌前缀决定 Flux 协议，其他自定义站名也能使用。查询为 `/api/v1/crossseed/lookup`，只提交 `pieces_sha1`，令牌通过认证头发送；只接受查询过的分片指纹和有效种子编号，同指纹多个候选保留并去重。下载使用 `/api/v1/crossseed/dl/{id}`，只跟随同协议、同主机、同端口的临时下载跳转，最多 3 次，不把令牌转发到站外。各协议最终共用原来的暂停添加、文件核验和强制校验流程。

只在 IYUU 查询成功后查询缺少命中的目标站点；IYUU 失败或冷却时不触发 Pieces。请求间隔默认 1 秒，限流冷却会跨运行和重载保留，空命中缓存 15 分钟。每轮最多新增默认 20 颗，可在高级选项调整。

qBittorrent 通过导出接口读取源种子。Transmission 可在高级选项按 `下载器名称=/MoviePilot内可读的种子目录` 配置已经挂载的目录。目标种子须通过分片、文件大小、完整布局及下载器实际文件名核验，暂停添加后强制校验至 100%，再按自动开始设置做种。主辅分离需目标下载器已有相同完整源任务，用其真实路径确认数据可用。未满足条件会显示具体跳过或失败原因。

设置页不展示铺种运行明细或历史记录。已添加任务继续由公共校验队列处理；辅种来源记录兼容原 IYUU 历史，支持后续补全标签。

## 自动删除

先预览命中，再暂停调试，核对后才正式删种——这个顺序由服务端确认记录保证，哼，不靠按钮旁的一句提醒。

自动删除默认关闭。每条规则选择一个或多个 QB/TR 下载器，支持名称、保存路径、Tracker、分类和标签正则，以及分享率、累计做种时间、添加时间、体积和实际上传速度阈值。所有填写的条件同时满足，排除优先；未知字段不会冒充零值。

半小时不用换单位，最少做种小时填写 `0.5` 即可；旧配置和服务端判断继续使用小时。做种门槛与扫描周期是两件事，达到门槛后仍要等待扫描并满足其他条件。

调试与正式规则共用固定间隔或 Cron，默认 5 分钟，每轮最多处置 20 个任务。只读预览立即计算，不改变任务或连续计数；手动运行不重置定时周期，连续有效采样之间仍须满足间隔。暂停后的零速度不参与低速计数。

调试暂停保留命中前证据和保护，下载中心内部转种、辅种、做种校验避让这些任务。确认规则时可以明确接受选定暂停任务的历史证据；确认本身不删除，实际处置等下一轮或手动运行。关键条件变化使确认失效；其他规则和同步删除保护继续生效。

正式动作可选仅删种保留数据，或删除种子及下载数据。数据删除须填写 MP 容器内允许目录，并检查精确文件、共享下载任务和媒体库引用；无法核验时保留暂停待复核。只按清单删除普通文件，不整包递归删盘，也不级联 Emby 或网盘删除。

一键停止复用模块总开关，保留暂停保护和在途结果。已经发给下载器的请求仍须回读；重载后旧未决任务不自动重放。执行记录可以查看依据、解除自己的保护或明确恢复原运行状态。

配置页保留3.3.16原有运行链路，只在原六条后补上同步删除与自动删除。详情页保留原四项统计、需要关注、速度监控/上传限速运行详情和功能状态，在原模块卡片后补齐站点标签、同步删除、自动删除。哼，补齐就在原位置补，不再重排两页或加一套总览。

原链路名称、步骤、顺序、间距和主题样式保持，配置页没有新增状态胶囊、说明列表或模块指标展开区；详情页没有插入运行链路。同步删除待处理可进入对应详情，忽略行为继续保留。配置页按基础设置、条件筛选、高级选项分类，保留已有监控与限速运行状态入口；自动删除的匹配条件在条件筛选，删除动作、连续采样与正式确认在高级选项，执行记录只在详情页展示。自动删除及同步删除首次打开才加载，切换配置标签保留草稿，隐藏自动删除配置时停止页面轮询。首屏只创建当前配置面板，下载器、站点和总览各自就绪就显示。自动删除与其他分类共用底部“保存配置”。基础设置的“前往规则处置与确认”可直接打开高级选项。启用的规则选择删除下载数据后，必须填写 MP 容器内的允许目录，动作选项和目录框都会指出缺项。点击底部保存先提交自动删除草稿，随后保存整页配置并显示结果。保存后停在当前分类，还能继续改下一项；点“关闭”才退出。

## 能力构成

前端每次构建按实际内容选择独立资源入口，并保留旧入口仍可能引用的文件。同版本调整界面后，重新加载 MP 页面即可获取新入口；哼，旧页面还没关，资源可不能先被清走。构建文件的一致性与浏览器实际显示分别验证。

速度监控基础设置采用等宽两列，开关放在标题旁，小屏改为一列。总览中的同步删除待处理提示可以直接打开详情，并默认只显示待处理记录；关闭详情后配置草稿保留。记录会说明无法重试的具体原因。尚未生成执行计划、没有已执行操作和保护引用的失败记录，管理员点“忽略”即可移出待处理，历史显示“已忽略”，不用填写原因或再次确认。忽略只关闭旧提醒，文件、种子与保护保留；核验后重试可能继续删除，仍须单独确认。

同组配置使用统一列距、行距和顶部对齐，字段说明放在各自输入框下方。“采样与判定”的四项在桌面同一行，转移高级开关也合为一组；实际可用宽度不足时才换行。独立数值项保持紧凑宽度，长路径和正则保留编辑空间；原配置分类、字段及运行总览继续沿用。

管理权限在同一次登录里复用已核验结果，配置和详情往返不重新联网等待；刷新页面、换登录身份、认证或权限拒绝、手动重新检查后再次核验。结果只保存在浏览器内存，实际写入仍由后端逐次授权。哼，不能把服务器启动时的一次检查，当成之后每个登录用户都有同样权限。

命名、归档、同步删除、自动删除执行记录和诊断页最近失败共用固定两行高度的历史列表。时间在左，名称填满中间宽度，状态上下居中并紧靠右侧「明细」。名称最多显示两行，完整名称、失败原因、关联路径及补刀、恢复、重试、忽略等操作可展开查看。长文件名终于能用上中间这块空间了，真是的。

- 转移做种：从源下载器复制种子到目标下载器，支持路径映射、删除源任务、删除重复任务。
- IYUU 辅种：扫描可辅种任务，查询 IYUU 并把辅种种子写入指定下载器。
- 同步删除：接收 Emby 媒体删除或宿主源文件删除事件，关联本插件的转种/辅种历史，保留合集未删除内容。源文件删除事件直接使用持久转种关系，即使整理记录已删除也能定位关联任务；清理前核验任务身份和文件范围。
- 种子重命名：按 MoviePilot 识别结果与原始发布名模板重命名，支持补刀与恢复原名。
- 站点标签：按 tracker 域名映射站点名，支持临时标签清理，并可预览补全站点、转种、IYUU 铺种标签；补全仅追加可由当前 tracker 或下载中心历史确认的缺失标签。
- 做种校验：转移或辅种后登记队列，后台轮询任务状态并按配置自动开始做种。
- 速度监控：按下载器建立稳健速度基准，识别异常下载会话并提供处置入口。
- 上传限速：为 qBittorrent 与 Transmission 写入全局上传上限，并按站点合计上限分配额度。

## 启用前提

插件总开关 `enabled` 之外，每项能力各有独立门禁；任意一项满足即视为运行中，配置不全的能力只保留配置意图，不会执行。

| 能力 | 生效条件 |
| --- | --- |
| 转移做种 | `transfer_enabled` 开启，且已填写 `fromdownloader`、`todownloader`、`fromtorrentpath` |
| IYUU 辅种 | `iyuu_enabled` 开启，且已填写 `iyuu_token` 与至少一个 `iyuu_downloaders` |
| 速度监控 | `speed_monitor_enabled` 开启并选择下载器；`manual` 模式下每个下载器必须填写正数手动基准 |
| 上传限速 | `upload_limit_enabled` 开启并选择下载器，且每个下载器都填写正数 `upload_limit_downloader_limits_kib` |
| 同步删除 | `sync_delete_enabled` 开启、选择 Emby 服务器并填写对应映射；删除下载源还需填写允许的源目录 |

## 配置要点

- `delay_minutes`、`transfer_fallback_enabled`、`transfer_fallback_interval_minutes`：转移延迟与兜底扫描周期。
- `nolabels`、`includelabels`、`includecategory`、`nopaths`：转移任务的标签、分类与路径筛选。
- `frompath`、`topath`：源与目标下载器之间的保存路径映射。
- `deletesource`、`deleteduplicate`、`add_torrent_tags`、`remainoldcat`、`remainoldtag`：转移后的处置与标签保留策略。
- `remainoldtag=true` 保留源标签，关闭时仅写入配置的附加标签；后续添加站名会保留目标现有标签，qBittorrent 与 Transmission 行为一致。
- `rename_movie_format`、`rename_tv_format`、`rename_exclude_dirs`：重命名模板与排除目录。
- `tag_siteprefix`、`tag_tracker_mappings_str`：站点标签前缀与自定义 tracker 映射。
- `iyuu_sites`、`iyuu_nolabels`、`iyuu_nopaths`、`iyuu_size`、`iyuu_labelsafterseed`、`iyuu_categoryafterseed`：辅种范围与辅种后的标签分类。
- `seed_autostart`、`seed_skipverify`、`seed_check_interval`、`seed_max_wait_minutes`：做种校验行为与等待上限。
- `speed_monitor_mode`、`speed_monitor_tolerance`、`speed_monitor_min_samples`、`speed_monitor_interval_seconds`、`speed_monitor_grace_minutes`、`speed_monitor_consecutive_abnormal_samples`：基准来源、判定容忍度、采样与宽限。
- `speed_monitor_exclude_categories`：按逗号分隔的分类关键词；qB 分类或 Transmission group 命中后不建立速度监控会话。
- `upload_limit_site_rules`、`upload_limit_grace_minutes`：站点合计上限与新种宽限；站点值为空或 `0` 时不写单种限速。
- `notify`、`speed_monitor_notification_type`：通知开关与消息通道。
- 速度告警与操作结果在 Telegram 使用 HTML，并更新原卡片；其他渠道及辅种、转移统计使用纯文本。

## 运行流程

1. 转移做种在整理完成事件后按 `delay_minutes` 延迟执行，后续事件不会推迟已排定的最早时间；同一种子的重复事件合并，其余到期批次依次接续，兜底扫描按周期补齐漏掉的任务。
2. 转移成功后按模板执行重命名并写入站点标签，失败记录进入重命名历史，可单条或批量补刀。
3. 连续补刀失败的记录自动归档，归档后跳过后续兜底扫描，可直接补刀、手动恢复或删除；直接补刀成功后移出归档，重命名失败则保留归档并更新原因与次数。
4. 转移与辅种完成的种子登记做种校验队列，后台线程轮询并按配置自动开始做种。
5. 速度监控按采样周期建立基准，连续异常样本达到阈值后在总览暴露处置入口。
6. 上传限速以 30 秒协调周期读取实时上传流量，在下载器全局上限内为受限站点等权分配额度。

## 边界与限制

- 目标下载器为 Transmission 时，种子重命名、命名补刀和恢复原名不生效，配置页与运行诊断会明确提示。
- 上传限速默认关闭；`allocated_kib` 只是插件写入的额度，不代表实际吞吐或 Peer 能力。
- 普通 `stop_service()` 只停止协调 worker，下载器保留最后写入值；只有明确停用上传限速时才按 compare-and-set 恢复原值。
- 扫描站点标签只追加 `{limit_kib: 0}`；未知标签、无标签和多站点标签的种子不写单种限速。
- 原始种子名被污染且无可信候选时跳过自动重命名，不会用脏名字套模板。
- IYUU 查询带限速与 Token/站点绑定预检，遇到服务端异常、空响应或限流连续失败时停止本轮任务。
- 35 条插件 API 全部要求 `bear` 认证，Vue 组件使用宿主注入的实例 ID，不硬编码源插件路径；管理操作还要求管理员身份。
- 运行状态、队列、缓存和锁按插件实例隔离，多实例之间不共享。

## 常见故障

| 现象 | 可能原因 | 处理方向 |
| --- | --- | --- |
| 插件显示未运行 | 各项能力门禁均未满足 | 按上表补齐对应必填项后保存 |
| 转移不触发 | 源/目标下载器或种子目录未填写，或任务被标签、分类、路径规则过滤 | 查看运行诊断中的转移配置检查与筛选条件 |
| 重命名保持原名 | 目标下载器为 Transmission，或原始发布名不可信 | 改用 qBittorrent 目标，或在重命名历史中手动补刀 |
| 辅种无结果 | Token 无效、站点未绑定或体积/标签过滤过严 | 核对 IYUU Token 与站点绑定，放宽 `iyuu_size` 与标签过滤 |
| 站点标签为空 | tracker 域名未命中内置映射 | 在 `tag_tracker_mappings_str` 补充自定义映射 |
| 速度监控无基准 | 采样不足或 `manual` 模式缺少手动基准 | 等待样本积累，或为每个选中下载器填写正数基准 |
| 上传额度未写入 | 下载器全局上限为空或站点合计上限为 `0` | 填写正数下载器上限，并为需要限速的站点填写正数合计上限 |

## 运行要求

- MoviePilot `>= 3.2.6`，使用已核验的调度及查询 SDK；本批目标运行实例为 `3.2.7`
- MoviePilot V3 原生插件格式与 Vue 联邦渲染
- 至少一个可用下载器；转移做种需要源与目标两个下载器
- IYUU 辅种需要有效 IYUU Token 与已绑定站点

## Emby 同步删除

同步删除默认关闭。启用前在“同步删除”填写服务器和路径映射；允许清理的下载源目录及可选保护目录放在默认折叠的“高级设置 · 删除范围”。同一文件只交给一个执行方删除，Emby 继续使用神医 `deep.delete` 通知。

下载目录迁移后，可在高级设置填写“历史源路径映射”，格式为 `历史目录#当前 MP 容器目录`，一行一条。当前目录须属于允许的下载源目录；按完整目录边界做一次最长匹配，同时检查历史和当前路径的下载/整理引用，保留宿主记录的原始路径。禁止根目录、循环和串联映射；两个路径同时存在时须为同一实体。文件仍存在、被新下载引用或任务已重建时停止自动删除。配置变化或升级前缺少快照的旧失败事件均不能直接重放；映射生效不会自动补删历史遗留任务。

网盘交由 Muvyo 等外部服务时，关闭“删除网盘文件”，并按需保留“删除下载源文件”“移除源种、转种和辅种”“清理整理记录”。关闭后本插件不查询、不删除网盘，四段映射也只依据本地文件和历史身份处理；路径映射仍须保留用于定位关联。本地处理不等待外部服务，也不证明网盘已删除，两边的完成状态需分别查看。

配置页分为“本地整理到本地”和“本地整理到网盘（STRM）”，两组映射可同时使用。目录按完整一行显示，长路径自动换行、增高，不再提供填写模式切换。115 插件上传生成 STRM 时可由下载中心处理网盘；Muvyo 等容器上传时可关闭网盘删除。当前云端执行支持已核验的 `115网盘Plus`，存储插件继续负责鉴权。

先整理到本地、再上传网盘的流程可填写第四段：`Emby路径#MP本地STRM路径#网盘目录#本地整理目录`。前三段保持兼容，第四段为空等同三段；该目录与网盘目录的相对路径必须对应。插件只按明确映射关联本地整理记录，并核验本地副本、历史文件大小与云端实体；副本已移走时须有可信的历史大小。删除下载源开关开启时也清理存在的本地整理副本，关闭则保留；已不存在的副本不重复删除，路径重现时停止旧任务。

关联查询使用当前下载中心实例的 `<下载器>-<hash>`、`iyuu_<hash>` 与母种反查记录，兼容已有历史，不要求安装独立 TorrentTransfer/IYUUAutoSeed。电影或单集精确处理；整季/整剧同时限制媒体身份与目录范围。整包仍有其它媒体文件则暂停种子，全部内容已处理才移除任务；文件单独清理，移除任务不让下载器整包删盘。

执行前保存目标快照，开启网盘删除时先核验网盘处理成功，再继续对应源文件与记录；关闭时跳过网盘阶段。失败在详情页“同步删除”中保留阶段和原因，可重新核验后重试。配置变化、同路径文件替换或任务重建时停止旧任务。重新加载后的未决任务不会自动重放，转种/辅种/校验流程也不会重新启动被本功能保护的旧任务。

下载中心插件日志记录同步删除的受理、开始、关联和完成结果，带媒体名与任务 ID。结果区分实际删除、原已不存在和合集暂停保留；关闭“发送结果通知”仍记录日志。

“删除下载源文件”和“移除源种、转种和辅种”独立生效；只移除种子时保留源文件，不把下载文件状态标记为已删除。两项都关闭时不访问下载器。关联任务仍需使用配置的源目录核验路径；同批多个媒体的相对路径只在各自关联种子链内匹配。失败重试前重新核验文件身份、任务重建及新增整理引用。

转移配置无效仅关闭转移功能，不关闭同步删除、辅种及其它独立能力。清空配置后所有能力回到默认关闭；停止或重载后，等锁任务和在途校验查询不能在新周期继续启动种子。升级前已生成的旧版删除清单保留进度供人工核验，不直接重放或自动扩大重试范围。

日常删除自动处理，无需逐次确认或填写单集路径。配置页移除普通删除通知、匹配预览和无记录强删入口；保存配置时关闭旧的普通通知和无记录强删选项。局部合集会保留数据与暂停任务；无法唯一确定的目标保留待处理。源文件清理只移除允许根之内的精确文件、同名字幕/NFO及空的本地父目录，保留根目录和未确认归属的附件。

### 转种卡片统计口径

显示顺序为“今日 · 兜底 · 累计”：今日为当天转种成功数，兜底为当天兜底扫描成功数（属于今日的子集），累计为截至昨日的成功数。次日今日与兜底归零，昨日成功纳入累计；底层全时段总量保留，避免重复累计或丢失历史。

IYUU 卡片显示“成功 · 失败 · 累计”：成功与失败仅统计当天，累计为截至昨日的成功数；次日当日成功、失败归零，只有昨日成功纳入累计，失败不计入累计。

管理权限：修改限速、重命名、标签清理及历史维护仅管理员可执行；普通登录用户保留查看能力。权限读取失败时管理按钮保持禁用。
