## 2. 最终目标与完成定义

AgentRank 不再只是一次性生成榜单，而是成为可审计、可纠正、可持续学习的 CinePilot Agent：以真实播放事实、用户明确反馈和已确认记忆为证据，在安全候选充足时始终给出 5 条榜单；用户能看懂每条推荐依据、评论错误判断、与 Agent 对话并决定是否把新理解写入长期画像。

`v1.0.0` 只有同时满足以下条件才算完成：

1. 喜欢、不喜欢、忽略语义严格分离；忽略只排除作品，不改变口味。
2. 用户动作异步进入反馈理解队列，页面不等待 LLM；失败可见、可重试且不污染画像。
3. 长期画像变化必须经过“Agent 复述 -> 变化预览 -> 用户确认 -> 记忆投影”；未回复、拒绝或关闭当前问询均不改变长期画像。
4. 删除或纠正过的标签以墓碑和 `supersedes` 保留，任何重放、乱序回调或新一轮画像都不能将其静默复活。
5. 现有十项配置权重继续作为基准；学习只生成有界增量，最终排序与百分比支持度由版本化确定性策略计算，不采用 LLM 自报置信度。
6. 每条作品只展示结构化“Agent分析”，不展示原始思维链；每条判断均可打开评论窗口，评论会生成可追溯的新事件。
7. 提供独立 CinePilot Agent 对话窗口。消息发送后立即持久化并返回受理，Agent 在后台串行处理；Agent 可解释、提问和提出变更，但所有写操作必须由用户确认。
8. 安全候选充足时榜单固定 5 条；只有完成全部硬过滤后确实不足 5 条才允许少于 5 条，并展示明确原因。
9. 订阅、入库和后续播放采用状态复查归因。`nativeSubscribe()` 返回只表示原生交互已接管，绝不记录为订阅成功。
10. 运行历史展示实际供应商与模型名；Agent Tokens 管理插件未安装或未接管时，明确记录回退到 MoviePilot 系统 LLM。
11. 推荐与简介各为不超过 30 个中文字符的语义总结，不得用机械截断造成丢字或残句。
12. 仪表盘、详情页和发现页在桌面与移动端无重叠、无横向溢出，所有交互均可达；发现页和详情页完全复用同一个 `Page.vue` 业务组件且功能一致。
13. 数据可导出，可单独重置学习，可彻底重置；候选快照、对话和事件日志有明确保留策略，不保存令牌、Cookie、地址或原始思维链。
14. 全部自动化测试、评估集、Vue 构建、MP 本地同步与运行态验收通过；正式 push、合入 `main` 和发布均取得用户明确确认。
15. 推荐动作顺序固定为“分析 -> 置信度 -> 订阅 -> TMDB -> 忽略 -> 喜欢 -> 不喜欢”；响应式换行不改变顺序，喜欢/不喜欢与其他操作使用同尺寸图标、文字和 tonal 样式。
16. 所有用户可见“专属影评师”统一为 `CinePilot Agent`；内部 `conversation` API、持久化键和模型标识不迁移。
17. 待处理文案按类型固定为“确认执行/拒绝执行”“确认采纳/拒绝采纳”“提交回答/关闭问询”；偏好问询面向用户整体、动态从宽到细且保留自定义回答，不使用固定三问或任何时效提醒。
18. 榜单发现与识别复用 MoviePilot `TmdbChain`、`MediaChain` 和 TMDB 缓存，不在插件内复制持久化识别缓存；运行历史可审计缓存命中与未命中数量。

“符合用户心理”在本计划中被定义为可验证行为：真实播放记录和明确偏好优先；稳定动机至少有两条独立播放证据，或一项用户明确偏好；弃看仅是弱负向；观看动机只参与软排序；禁止推断人格、焦虑、孤独、疾病、创伤等敏感心理状态。它不是临床心理判断，也不以主观感觉替代测试。

## 4. 核心架构与所有权

```text
播放事实/发现候选/当前榜单
          |
          v
用户动作 API --鉴权--> FeedbackEvent 追加账本 --入队--> Feedback Worker
   |                         |                         |
   |                         |                         v
   |                         |                 受限理解 Agent
   |                         |                  /          \
   |                         |          明确可复述        有歧义
   |                         |             |                |
   |                         |             v                v
   |                         |      MemoryProposal    PendingQuestion
   |                         |             |                |
   |                         |             +---- 用户确认 --+
   |                         |                         |
   |                         v                         v
   |                   审计/重放依据        MemoryProjector(revision++)
   |                                                   |
   +--> 当前榜单即时语义                               v
       喜欢:保留强正向                       基准权重 + 已确认学习增量
       不喜欢:移出并安全补位                           |
       忽略:仅排除                                     v
                                             DeterministicScorer
                                                       |
                                                       v
                                          固定5条 + 支持度 + Agent分析
```

边界规则：

- Controller 只做认证、入参校验和服务编排，不写学习逻辑。
- Service 拥有反馈语义、队列、记忆投影、评分、归因和生命周期。
- Adapter 只接 MoviePilot Agent、订阅、媒体库、播放与通知，不制定口味策略。
- Model 定义不可变事件、提案、记忆、分析、对话和策略快照。
- Repository 负责 `profile_id` 隔离、事件序号、幂等、分段保存、原子替换和迁移。
- LLM 只能生成结构化理解、证据说明和变更提案；不能直接写数据、订阅、忽略、重置或改变权重。
- 最终 5 条顺序、补位资格、学习增量边界和百分比均由确定性代码决定。

### 4.1 内置人设、记忆与 skills

- 内置人设固定为“谨慎、具体、尊重用户纠正的 CinePilot Agent”，负责解释内容匹配、承认不确定性并提出可撤销的理解；不得扮演心理医生，也不得把用户反馈说成既定人格。
- 用户在配置页提供的提示词继续作为可编辑软排序指令，默认覆盖题材、主创、地区、年代、风格，以及情绪体验、认知满足、叙事投入、熟悉与新奇平衡、节奏与完成感五类观看动机。硬安全规则、证据门槛、写操作确认和输出 schema 不允许被配置提示词覆盖。
- 内置 skills 不是 MoviePilot 通用动态技能，而是 `service/critic_skills.py` 中版本化、无副作用的固定分析程序：`summarize_evidence`、`understand_feedback`、`compare_conflicts`、`propose_memory_change`、`explain_recommendation`、`ask_clarification`。它们只组装受信上下文和结构化 schema，不自行调用外部工具。
- 长期记忆只读取 `PreferenceMemory` 已确认投影；会话摘要、待确认提案和原始事件不能冒充已确认记忆。人设版本、skill 版本、prompt fingerprint、memory revision 和 policy version 都写入分析/运行历史，支持重放和回溯。
- Agent 的工具白名单按角色扩展只读工具，继续禁止宿主通用 ToolFactory、外部 MCP、子代理、文件、配置、通知和订阅工具。

## 5. 稳定数据契约

新增模型建议位于 `plugins.v2/agentrank/model/feedback.py`、`memory.py`、`analysis.py`、`conversation.py`、`policy.py`：

- `FeedbackEvent`：`event_id`、`profile_id`、`sequence`、`kind`、`candidate_id`、`run_id`、`analysis_id`、`comment`、`created_by_mp_user_id`、`created_at`、`idempotency_key`、`supersedes`、`status`、`schema_version`。
- `MemoryProposal`：Agent 对用户意图的复述、拟增加/削弱/归档的偏好、证据引用、影响预览、来源事件序号、状态和过期时间。
- `PreferenceMemory`：只保存已确认断言；每项包含类别、极性、强度、确定性、独立证据引用、状态、墓碑、`supersedes`；根对象持有单调递增 `memory_revision`。
- `AnalysisRecord`：推荐证据、反证、不确定点、确定性策略贡献、来源 run/policy/memory revision；不含内部推理 token 或原始思维链。
- `PendingQuestion`：面向整体偏好的问题、偏好维度、由宽到细的探索层级、置信度缺口、证据引用、2 至 5 个动态选项、自定义回答入口和状态。未回复或关闭不投影记忆；关闭只结束当前问询，不产生负向信号。
- `ConversationMessage`：幂等消息 ID、角色、内容、`queued/processing/completed/retryable_failed` 状态与失败原因；`ConversationThread` 保存有界消息摘要、相关事件/分析引用和待处理命令，写命令只能进入 `MemoryProposal` 或受控动作确认。
- `PolicySnapshot`：`policy_version`、十项基准权重、已确认学习增量、证据确定性、有效权重、校准参数、生成时间。
- `OutcomeAttribution`：推荐、原生订阅已打开、订阅已确认、入库、播放等状态及证据时间；不把打开抽屉当成成功。

持久化采用按 `profile_id` 隔离的命名空间；事件日志使用有界分段和单调序号，避免单键无限膨胀。建议键前缀：

- `feedback_event_index:profile:<profile_id>`
- `feedback_event_segment:profile:<profile_id>:<segment>`
- `feedback_queue:profile:<profile_id>`
- `preference_memory:profile:<profile_id>`
- `pending_questions:profile:<profile_id>`
- `conversation:profile:<profile_id>`
- `policy_snapshot:profile:<profile_id>`
- `outcome_attribution:profile:<profile_id>`

旧榜单、画像、归档和运行历史必须原位兼容读取；迁移只新增数据，不重写用户现有配置。旧 `reminder_policy`、`next_remind_at` 等字段只兼容读取并忽略，运行时不再调度且新数据不再生成提醒时间。损坏的新 schema 数据应隔离并记录恢复事件，不得清空旧榜单。

## 6. 确定性学习与排序规则

1. 十项基准权重继续来自 `model/config.py::WEIGHT_DEFAULTS` 和用户配置。
2. 每项已确认学习增量限制在 `[-0.25, +0.25]`；有效权重为 `clamp(base + delta * certainty, 0, 1)`。
3. “稳定动机”必须满足两条相互独立的播放证据，或一条用户明确添加/确认的偏好。播放同一作品的多个事件不能冒充独立证据。
4. 弃看只产生弱负向证据，单独不得形成硬过滤或稳定负向标签。
5. 喜欢是强正向事件；不喜欢是强负向事件并立即移出当前榜单及补位池；忽略只写排除归档，不生成口味增量。
6. LLM 输出候选相关证据类别和说明；`DeterministicScorer` 依据受信媒体元数据、播放事实和已确认记忆重算贡献。无法由受信数据支撑的声明不计分。
7. 支持度为“已验证正向贡献减去反向贡献”占可用加权证据的归一化百分比，并记录 `policy_version`；不是模型自报信心。
8. 排序以确定性分数为主；分数相同时才使用已校验的 Agent 顺序、候选冻结顺序和 `candidate_id` 依次稳定破同分。
9. 本地补位也必须计算同一支持度与结构化分析，且标记 `selection_source=safe_fallback`，不能伪装成 Agent 直接选择。
10. 推荐理由与简介由 LLM 生成完整短句，经校验后最多一次定向重写；仍不合格时使用确定性模板总结，禁止字符串硬切 30 字。

实现面：

- `plugins.v2/agentrank/ai_spec/plugin_context.md`
- `plugins.v2/agentrank/controller/api.py`
- `plugins.v2/agentrank/adapter/agent.py`
- `plugins.v2/agentrank/service/prompt.py`
- `plugins.v2/agentrank/tests/test_api_controller.py`
- `plugins.v2/agentrank/tests/test_agent_adapter.py`
- `tests/static/test_agentrank_contracts.py`

工作单元：

- 1.1 同步规格：写入喜欢/不喜欢/忽略、结构化分析、确认式记忆、确定性支持度、30 字语义总结、Agent Tokens 回退和 `nativeSubscribe` 非成功语义；移除旧十五字规则。
- 1.2 为所有读取和写入 profile 数据的 bear 端点注入 `TokenPayload = Depends(verify_token)`。超级用户可访问全部已配置 profile；普通用户只可访问配置中的 `profile_access_map[str(token.sub)]`，默认空集合，不以相似用户名猜测身份。
- 1.3 修复排序上下文边界：排序 Agent 只接收归档作品的最小 `candidate_id/reason/timestamp`，不得接收归档中保存的完整推荐载荷；新增内容注入与越权回归测试。
- 1.4 扩展受限 Agent 结果采集契约，保存实际 `provider_id/selected_provider_name/model/model_call_count`；Agent Tokens 未接管时明确标识 `moviepilot_system`，不复制或绕过宿主 LLM 选择链。

硬验收：

- `plugin_context.md` 与本文 14 条完成定义无冲突，且不存在旧十五字规则。
- 普通用户跨 profile 读取和写入均返回 403；超级用户正常；缺失映射不会回退到默认 profile。
- 排序提示和四个工具返回中没有归档推荐的简介、海报、来源 ID 等完整载荷。
- Agent 适配器测试能区分 Agent Tokens 接管与 MoviePilot 系统回退，并记录真实模型名而不是调用数量。
- 阶段相关 pytest 命令退出码为 0，结果写入进度账本。

失败恢复：契约测试失败时只回滚当前工作单元；不迁移数据、不继续 Phase 2。鉴权不确定时默认拒绝访问。

提交边界：每个工作单元独立提交；建议 scope 为 `docs(agentrank)`、`fix(agentrank)`、`test(agentrank)`。

自动推进：全部硬验收通过并记录后直接进入 Phase 2，不请求阶段确认。

### Phase 2：反馈事件账本、迁移与数据生命周期

目标：建立可幂等、可重放、可导出、可清理的反馈事实层，不让 Agent 输出直接成为事实。

实现面：

- 新增 `model/feedback.py`、`model/memory.py`、`model/policy.py`
- 扩展 `storage/repository.py`
- 新增 `service/data_lifecycle.py`
- 扩展 `model/config.py`、`controller/api.py`、`service/lifecycle.py`
- 新增 `tests/test_feedback_repository.py`、`tests/test_data_lifecycle.py`

工作单元：

- 2.1 实现按 profile 分段的追加事件账本、单调 `sequence`、幂等键和进程内锁；重复回调只返回原事件，不重复学习。
- 2.2 实现 `PreferenceMemory`、墓碑、`supersedes` 和 `memory_revision`；投影必须按 sequence 重放，过期乱序结果只能记录为 superseded，不能覆盖新 revision。
- 2.3 增加兼容迁移：旧画像、榜单、归档、标签和历史保持可读；新键缺失时创建空 schema，迁移失败保留旧状态并可见报错。

## 13. 已锁定决策记录

| 决策 | 原因 | 拒绝方案 |

| 记忆变化需要确认 | 用户拥有最终解释权 | Agent 静默改画像 |
| 结构化 Agent分析 | 可纠正、可审计且不泄漏原始推理 | 展示原始思维链 |
| 确定性支持度 | 可重放、可校准 | 信任 LLM 自报 confidence |
| 现有权重 + 有界学习增量 | 复用用户配置并控制漂移 | 新模型完全替换权重 |
| 墓碑 + supersedes + revision | 防止删除标签复活和乱序覆盖 | 简单覆盖最新 JSON |
| 原生订阅需状态复查 | 打开抽屉不等于完成订阅 | 将 nativeSubscribe 返回当成功 |
| Agent Tokens 可选 | 保持插件独立可用 | 未安装时禁用 AgentRank |
| 非超级用户显式映射 | 不以用户名猜测跨系统身份 | 自动模糊匹配 Emby 用户 |
| 图标靠形状和状态区分 | 国内用户习惯且兼顾无障碍 | 固定绿色赞/红色踩作为唯一语义 |

| 动态整体偏好问询 | 以信息增益逐步了解真实口味 | 固定三个问题或每次只问单部作品 |
| 仅保留“提交回答/关闭问询” | 同时覆盖预设选项和自定义回答 | “立即回答”或无提交动作 |
| 完整移除问询提醒 | 避免催促和多余调度 | 保留 1/3/7 天或不提醒 |

## 14. 残余风险与发布裁决

- 2026-07-31 前完成 8 个阶段时间紧。任何高严重度数据、权限、隐私或发布问题优先于日期。
- MoviePilot 和 Agent Tokens 的运行时版本可能在计划执行期间变化；每回合 smoke 和 Phase 1/8 宿主契约回读用于发现漂移。
- 用户口味没有绝对真值。发布标准是证据规则、可纠正性、确定性重放和固定评估集，而不是宣称模型永远推荐正确。
- 真实订阅/入库/播放归因依赖宿主状态可读性；不可读时保持 pending，不把缺失证据解释为成功或失败。
- 插件存储不是通用事件数据库；分段、保留和导出必须通过容量与故障注入测试后才能发布。
- 动态问询若缺少重复冷却和信息增益约束会形成问卷轰炸；Task 8.2 的 eval 与运行态验收必须同时覆盖频率和主题收敛。
- 429 与上游慢响应必须共享 90 秒后端总预算；任何重试若重置计时器都会导致用户长期看到 processing，属于发布阻断。
